Security information

Consotelo is engineered with a focus on data privacy, multi-tenant separation, and verifiable document integrity. This page describes our security controls and our responsible disclosure programme.

Our approach to platform security

Consulting relationships involve sensitive commercial discussions, intellectual property, and financial records. Rather than relying on generic marketing claims, Consotelo enforces security through concrete technical boundaries embedded directly within our software architecture.

Core security controls

Multi-tenant boundary enforcement

Every advisory practice operates within an isolated tenant boundary. Isolation is enforced server-side at the database query level, ensuring that consultants and clients cannot access or modify records belonging to other organisations.

Cryptographic token hashing

Session authentication tokens are cryptographically generated using secure random bytes and persisted exclusively as SHA-256 hashes. Plaintext tokens exist only in memory on the client device during active sessions.

Encrypted multi-factor authentication

Privileged consultant accounts require multi-factor authentication using time-based one-time passwords. TOTP secret keys are encrypted at rest using AES-128-CBC encryption with dedicated master keys.

Tamper-evident document hashing

Every consultation agreement and tax invoice PDF is bound to a cryptographic SHA-256 byte digest. Prior to electronic acknowledgement, the client verifies that the downloaded document matches the approved revision.

Encrypted network transmission

All communications between client devices and our backend services use Transport Layer Security with modern cipher suites. Cleartext HTTP connections are rejected by the application.

Brute-force defence and rate limiting

Authentication endpoints employ exponential rate limiting and automatic temporary account locking to defend against automated credential stuffing and dictionary attacks.

Security of this public website

This public website is hosted as static HTML files on GitHub Pages. It contains no database connections, executes no server-side scripts, collects no personal data, and processes no financial transactions. Hosting static information separately from operational application services eliminates common web application vulnerabilities from this informational site.

Responsible vulnerability disclosure

We welcome constructive feedback and responsible vulnerability reports from independent security researchers and software engineers. If you discover a potential security vulnerability in Consotelo, we request that you disclose it to us responsibly:

  • Email your findings to our security team at rigour.consulting@gmail.com.
  • Specify "Security Vulnerability Report" in your subject line.
  • Provide detailed technical steps to reproduce the issue, including request payloads and system responses.
  • Do not attempt to access, alter, or destroy customer records or personal data belonging to other users.
  • Do not perform denial-of-service attacks or degrade the availability of our production systems.
  • Allow us a reasonable opportunity to assess and remediate the issue before disclosing details publicly.

Our response commitment

We acknowledge security reports within two Australian business days. Our engineering team prioritises security vulnerabilities based on severity, investigates root causes, and deploys verified corrections through our gated testing pipeline.
