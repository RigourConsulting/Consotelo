Security information

Publisher Rigour Consulting Location Perth, Western Australia Effective date 26/11/2026 Security contact rigour.consulting@gmail.com

Consotelo is engineered with a focus on data privacy, multi-tenant separation, and verifiable document integrity. This page describes our security controls and our responsible disclosure programme.

Our approach to platform security

Consulting relationships involve sensitive commercial discussions, intellectual property, and financial records. Rather than relying on generic marketing claims, Consotelo enforces security through concrete technical boundaries embedded directly within our software architecture.

Core security controls

Multi-tenant boundary enforcement

Every advisory practice operates within an isolated tenant boundary. Isolation is enforced server-side at the database query level, ensuring that consultants and clients cannot access or modify records belonging to other organisations.

Cryptographic token hashing & encrypted device storage

Session tokens are generated using cryptographically secure random bytes and stored server-side exclusively as SHA-256 hashes. On native Android and Windows devices, active session tokens are stored in OS-protected secure storage (Android Keystore / Windows DPAPI); web sessions use HTTP-only cookies with CSRF protection.

Authentication, authenticator-app MFA & passkey readiness

Accounts are protected by strong salted password hashing, database-backed login rate limiting, RFC 6238 authenticator-app two-step verification (with encrypted secrets and single-use SHA-256 recovery codes), per-session 15-minute step-up re-authentication for sensitive actions, device/session revocation, and immutable audit logs. Standards-based FIDO2/WebAuthn passkey and Windows Hello support is built in and activates when a practice connects to a permanent controlled HTTPS domain (rotating test tunnels are blocked). SMS one-time codes are intentionally disabled. Privileged platform administration is restricted to the trusted local environment.

Tamper-evident agreements & invoicing

Every consultation agreement and invoice PDF is bound to a SHA-256 digest. Clients may download and print an A4 agreement to sign by hand and upload a scanned or photographed copy (PDF, JPG or PNG), or sign electronically. Uploaded handwritten copies require manual consultant review and are not automatically treated as identity-verified. Finalised agreements are locked against silent replacement; subsequent changes require a new auditable amendment.

Encrypted network transmission

All remote communications between client devices and practice servers require verified HTTPS (TLS). Cleartext remote HTTP connections and arbitrary self-signed certificates are rejected by release builds.

Brute-force defence and rate limiting

Authentication endpoints employ exponential rate limiting and automatic temporary account locking to defend against automated credential stuffing and dictionary attacks.

Security of this public website

This public website is hosted as static HTML files on GitHub Pages. It contains no database connections, executes no server-side scripts, collects no personal data, and processes no financial transactions. Hosting static information separately from operational application services eliminates common web application vulnerabilities from this informational site.

Responsible vulnerability disclosure

We welcome constructive feedback and responsible vulnerability reports from independent security researchers and software engineers. If you discover a potential security vulnerability in Consotelo, we request that you disclose it to us responsibly:

  • Email your findings to our security team at rigour.consulting@gmail.com.
  • Specify "Security Vulnerability Report" in your subject line.
  • Provide detailed technical steps to reproduce the issue, including request payloads and system responses.
  • Do not attempt to access, alter, or destroy customer records or personal data belonging to other users.
  • Do not perform denial-of-service attacks or degrade the availability of our production systems.
  • Allow us a reasonable opportunity to assess and remediate the issue before disclosing details publicly.

Our response commitment

We acknowledge security reports within two Australian business days. Our engineering team prioritises security vulnerabilities based on severity, investigates root causes, and deploys verified corrections through our gated testing pipeline.

SMS handling & independent verification scope

Manual SMS vs optional automated SMS: On Android, Consotelo's Send SMS reminder action opens the device's own Messages app with a prefilled draft so the consultant reviews and chooses whether to send it. Consotelo does not request restricted SMS permissions (SEND_SMS/READ_SMS). Automated carrier SMS delivery is disabled by default and requires explicit practice opt-in and provider configuration.

Honest assurance boundary: No software system can guarantee absolute or perfect security, and Consotelo has not undergone an external paid penetration-testing certification. Security claims on this page describe controls verified in automated and local device testing.
